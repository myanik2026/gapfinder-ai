# GapFinder AI

GapFinder helps students discover what they do not know yet. It turns a
syllabus, notes, and past papers into a topic map, a source-grounded diagnostic
quiz, a topic-level gap report, and a revision plan that changes as the student
improves.

The central loop is:

**Upload → retrieve evidence → take a diagnostic → review mistakes → prioritize revision → retest**

## Features

- Upload PDF, TXT, and Markdown study material. A sample Biology course is
  included so the app can be explored immediately. Uploads are limited to
  eight files, 80,000 characters per file, and 400,000 characters total.
- Extract a topic map from syllabus headings and study notes.
- Generate five multiple-choice questions for a selected topic using Groq and
  passages retrieved from the student's material.
- Display a citation next to each question and explanation. The server maps
  model-selected evidence IDs back to retrieved passages, so displayed source
  excerpts are taken from the uploaded text rather than generated by the model.
- Score answers, explain the correct answer, and group results into weak
  (<60%), medium (60–79%), and strong (80%+) topics.
- Prioritize topics using the latest diagnostic score and whether they appear
  in an uploaded past-paper source. Fit the plan to the student's days and
  study hours, and recalculate after each attempt.
- Ask a study question and receive a material-grounded explanation with a
  source citation.
- Save the demo session, sources, study-time preferences, and attempts in
  browser local storage.
- Run a clearly labeled sample quiz without an API key. Real AI quiz generation
  and explanations require a Groq API key.

## Run locally

Requirements: Node.js 20.9 or later and npm.

```bash
cd gapfinder-ai
npm install
Copy-Item .env.example .env.local
```

Set `GROQ_API_KEY` in `.env.local` to a key from
[Groq Console](https://console.groq.com/keys). Keep this value private and do
not commit `.env.local`. The app uses the server-side model
`llama-3.3-70b-versatile`; the key is never sent to the browser.

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000), choose **Continue as demo
student**, and start with the included Biology material. The demo session does
not require a password. Add your own PDF, TXT, or Markdown files from **My
materials**.

Useful checks:

```bash
npm run lint
npm run build
```

## Deploy to Vercel

1. Push the `gapfinder-ai` folder to a GitHub repository.
2. Import that repository in [Vercel](https://vercel.com/new).
3. Add `GROQ_API_KEY` in **Project Settings → Environment Variables** for the
   environments you will use.
4. Deploy and open the generated URL. Keep the key in Vercel's environment
   settings; never put it in a `NEXT_PUBLIC_` variable.

The app uses the Node.js runtime for its study API route. The API route is
configured with a 30-second maximum duration.

## How the AI flow works

1. The browser extracts text from PDFs with PDF.js and stores source text in
   local storage. TXT and Markdown files are read as text.
2. When a student requests a quiz or explanation, the browser sends the
   selected topic, request, and source text to `POST /api/study`.
3. The server validates the request and splits material into paragraph-sized
   chunks. A lightweight lexical retriever ranks chunks by token overlap with
   the topic or question. Only the top matching passages are included in the
   model prompt.
4. The Vercel AI SDK requests structured output from Groq. The prompt requires
   the model to use only retrieved evidence and choose an evidence ID provided
   by the server.
5. The server validates the structured result, resolves each evidence ID to
   its original source name and excerpt, and returns those citations with the
   response. Unsupported evidence IDs are rejected.
6. Quiz grading is deterministic in the browser: selected options are compared
   with the answer indices returned in the quiz. The UI shows the explanation
   and citation for each question.
7. The revision plan is a transparent local calculation, not an LLM-generated
   schedule. It puts lower-scoring topics first and adds priority to topics
   found in a past-paper source. A new diagnostic updates the scores.

This is a small-assignment RAG implementation: it uses lexical retrieval and
does not use embeddings or a vector database. It is not a substitute for a
production learning platform.

## Data and demo limitations

- Uploaded material, the demo session, quiz attempts, and study-time settings
  are stored in the current browser's local storage. Clearing browser data
  clears this progress.
- Source text is sent to Groq only when the student requests an AI quiz or
  explanation; only the retrieved passages are included in the model prompt.
  The key stays on the server. Review Groq's current data policy before using
  sensitive materials.
- The sample quiz is fixed and is used only when the sample Biology materials
  are active and `GROQ_API_KEY` is not configured. The interface tells the
  student when it is using this sample mode.
- The demo sign-in is a local UX entry point, not authentication. There is no
  user account service, database, or cross-device sync.
- Topic extraction and retrieval are intentionally lightweight. Scanned PDFs
  without selectable text, unusual syllabus formats, and very large courses
  may need OCR, better parsing, embedding-based retrieval, and persistence.

src/
  app/

## Assignment focus

The main product output is the diagnosis and adaptive study plan, not an
open-ended chatbot. The assistant is an additional way to explain the same
student-provided material. For a walkthrough and interview practice, see
[INTERVIEW_PREP.md](./INTERVIEW_PREP.md).
